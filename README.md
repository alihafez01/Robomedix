# Robomedix

Robomedix is a final-year project prototype for symptom collection and preliminary health assessment. It combines a React web interface, a Django REST API, experimental machine-learning notebooks, and an ESP32 sensor sketch. The application can collect symptoms and follow-up answers, display temperature/heart-rate/oxygen readings from Firebase, and request disease and medicine predictions.

## Project Demo

[Watch the Robomedix demo video on Google Drive](https://drive.google.com/file/d/12smDPbvKHU3mdGDgEllm2mTO84fGUcXP/view?usp=sharing)

> **Important:** Robomedix is an educational prototype, not a medical device or a substitute for professional care. Its predictions and sensor readings are not clinically validated. Do not use it to diagnose, treat, or make urgent health decisions. Seek professional or emergency care when appropriate.

## Features

- React pages for home, contact, sign-up, login, chatbot, and medication views.
- A conversational symptom flow that uses a Groq-hosted Gemma model to classify input, extract symptoms, and generate follow-up questions.
- Django REST endpoints for account actions, chatbot sessions, sensor readings, disease prediction, and medicine prediction.
- A TensorFlow/Keras notebook that trains an experimental Transformer-based classifier using symptom categories and patient vitals.
- A separate PyTorch/Bio_ClinicalBERT notebook for multi-label medicine recommendation.
- An ESP32 sketch that sends DS18B20 temperature and MAX30105-derived values to Firebase Realtime Database.

## API Routes

The Django URL configuration currently exposes these routes at `http://localhost:8000`:

| Method | Route | Purpose |
| --- | --- | --- |
| GET, POST, other router actions | `/todos/` | Todo API generated by a DRF router |
| POST | `/signup/` | Create an account |
| POST | `/login/` | Authenticate an account |
| GET | `/sensors/` | Read the latest Firebase sensor values |
| POST | `/api/chatbot/message/` | Submit a symptom/chat message |
| POST | `/api/chatbot/followup/` | Submit an answer to a follow-up question |
| GET | `/api/chatbot/summary/` | Return the conversation summary and structured patient fields |
| POST | `/api/predict-disease/` | Request a disease prediction from structured patient fields |
| POST | `/api/predict-meds/` | Request medicine labels from `disease` and `symptoms` text |
| GET | `/admin/` | Django admin |

The React app currently calls the API at `http://localhost:8000`; its chatbot requests use cookie credentials for Django sessions.

## Configuration and Local Development

### Requirements

- Python 3.10 or newer is recommended based on the checked-in notebook execution metadata.
- Node.js and npm.
- A Groq API key for the chatbot.
- A Firebase Realtime Database and a Firebase service-account JSON file for sensor integration.
- The model and label artifacts required by the prediction code. These are not all included in Git.

There is currently no Python dependency manifest in this clone. The backend imports Django, Django REST Framework, `django-cors-headers`, `python-dotenv`, `langchain-groq`, `firebase-admin`, pandas, NumPy, scikit-learn, TensorFlow, PyTorch, and Transformers. Install compatible versions for your platform; TensorFlow and PyTorch installation options vary by operating system and hardware.

### Secrets

Create `Backend/.env` locally (it is ignored by Git):

```dotenv
DJANGO_SECRET_KEY=replace-with-a-long-random-secret
GROQ_API_KEY=replace-with-your-groq-key
FIREBASE_SERVICE_ACCOUNT_PATH=./firebase/service-account.json
FIREBASE_DATABASE_URL=https://YOUR-PROJECT-default-rtdb.firebaseio.com/
```

Place your Firebase service-account JSON at the configured path, or set `FIREBASE_SERVICE_ACCOUNT_PATH` to its local path. Never add `.env` files, service-account JSON files, Wi-Fi passwords, or API keys to Git. The ESP32 sketch uses placeholder values; configure its Wi-Fi and Firebase credentials locally before flashing it. Rotate any credentials that were previously committed or shared.

### Frontend

```powershell
cd UI/robomedix
npm install
npm start
```

The development server is normally available at `http://localhost:3000`. To create a production build, run `npm run build` in the same directory.

### Backend

After creating and activating a Python virtual environment, installing the dependencies above, and configuring the required local model/data files and Firebase credentials:

```powershell
cd Backend
python manage.py migrate
python manage.py runserver
```

These are the Django commands; see the implementation notes below before expecting a clean-clone startup. The React app expects the API on port `8000`, and Django CORS settings currently allow `http://localhost:3000`.

### Notebooks

Open either notebook in Jupyter or VS Code and run its cells in order. `Disease_Prediction.ipynb` reads `disease_diagnosis.csv` and trains/evaluates a TensorFlow/Keras classifier. `inferencepipeline.ipynb` loads Bio_ClinicalBERT and local PyTorch/label artifacts. The notebook files contain machine-specific paths in places; update those paths to your local artifact locations before running them.

## Implementation Notes

- `Backend/app/predict_disease.py` currently contains the full training workflow and reads the CSV using a machine-specific absolute path. It performs data loading/training when the module is imported; it does not load the checked-in `.h5` file as an inference-only model. A clean clone therefore needs code/path changes and local training data before this endpoint can work reliably.
- `Backend/app/inferencepipeline.py` expects `mlb.pkl` and `medicine_model.pt` at machine-specific paths. The medicine model and label binarizer are not available in a clean clone, so `/api/predict-meds/` is not ready to run without those artifacts and path configuration.
- The Firebase integration requires a valid service-account JSON and a database configured with the expected `/esp32/sensors` structure.
- The firmware's heart-rate and oxygen values are derived using prototype calculations and fallback random values; they are not validated clinical measurements. Its TLS client currently disables certificate verification and should not be used as-is in a production deployment.
- The Django settings and account/session flow are development-oriented. Configure production secrets, debug mode, allowed hosts, HTTPS, and authentication/session security before deployment.

## Safety and Privacy

The project handles health-related inputs. Use only data you are authorized to process, avoid committing patient data or model-training datasets, and do not send real patient information to third-party services without appropriate consent and safeguards. Model outputs are experimental and may be incorrect or unsafe.
